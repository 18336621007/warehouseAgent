## 三、第15课：多数据源接入（Doris / Trino 预留）

- `build_plan_from_semantic` 在方案中写入 `engine_candidates` 与 `cross_engine`；`execute_sql_node` 按候选链逐个引擎执行，连接/执行异常降级下一候选，校验失败不降级，跨引擎关联直接拒绝。
- 工具按引擎注册：`sql_query_trino / sql_query_hive / sql_query_doris`；安全校验三引擎统一（只读 + LIMIT + 白名单 + select * 门禁 + 分区过滤）。

## 四、第16课：并行查询执行（A2）

### 4.1 本课目标

把"用户一次问多个指标 / 多张表"的查询拆分为并行子查询，全部完成后归并结果再写回答；同时保留串行兜底与超时控制。

### 4.2 关键内容

- 子查询拆分：按指标 × 过滤条件分桶；同一过滤条件的不同指标可并行（每子查询独立 SQL）。
- 执行器：线程池并发执行 `execute_query`，每个子查询独立超时（默认 60s 可配），失败子查询单独记录、不影响其他子查询。
- 结果归并：按指标/维度对齐列，合成一张宽表或分块展示；落盘沿用 `result_store` 按会话/日期组织。
- 与 0 行自愈、`probe_values` 的交互：仅对失败/0 行的子查询触发，不整轮重跑。
- 保留 `MAX_PARALLEL_QUERIES` 与串行开关，结果量过大时降级串行。

### 4.3 验收标准

- 一次问"新增订单、退租订单、净增"三指标，总耗时接近单指标而非三者之和。
- 其中一个子查询失败/0 行，其余照常返回，回答中标注该指标未取到。
- 前端仍流式输出，思考/回答顺序不因并行而错乱。

## 五、第17课：检索评估与消融实验

### 5.1 本课目标

建立带标准答案的评估集，量化"语义层 grep / BM25 / 向量 / 混合"各路的命中率与端到端收益，指导后续取舍。

### 5.2 关键内容

- 评估集：从历史真实问答 + 优秀案例中抽取 50~100 条（问题 → 期望指标 id / 表 / 字段），按业务域分层。
- 指标：Recall@K、MRR、NDCG（检索层）；语义层命中率、SQL 首查成功率、回答正确率（端到端）。
- 消融：语义层优先 + RAG 兜底 vs 纯 RAG vs 纯 BM25 vs 纯向量，对比端到端正确率与平均轮次。
- 脚本化：`benchmark_models.py` 已有雏形，扩展为评估集运行器，输出对比报告。

### 5.3 验收标准

- 评估集可一键运行并输出报告；指标可追溯单条失败原因。
- 消融结论明确（如"语义层优先使首查成功率提升 X 个百分点"），作为后续优化依据。

## 六、第18课：语义案例闭环（指标案例 SQL + 优秀案例治理）

### 6.1 本课目标

把"优秀案例"沉淀回语义层：每个指标维护一段**案例 SQL**，当同一段 SQL 多次被 Evaluator 评为优秀案例时自动替换指标内案例，形成"指标口径 + 已验证 SQL"闭环。

### 6.2 关键内容

- 指标 YAML 增加 `example_sql`（可选字段）；命中指标时作为参考注入 SQL 生成。
- 优秀案例聚合：按指标 id 聚合历史优秀 SQL，同口径多次出现（阈值可配）时回写 `example_sql`，避免每次重新生成。
- 优秀案例生命周期：`prune_examples_by_scope` 基础上增加按指标归并、过期清理、口径变更时失效。
- 与 `search_semantic`、SQL 校验的关系：案例 SQL 仍须过 Guardrails，不允许绕过安全校验。

### 6.3 验收标准

- 某指标连续多次被评优的 SQL 自动沉淀为 `example_sql`，后续生成优先复用且可通过日志审计（`tools.called` / `semantic.match`）。
- 口径修改后旧案例失效，不污染新口径。

## 七、第19课：分析性查询系统化（基础 + 高级）

### 7.1 本课目标

把分析性查询从"LLM 自由发挥"收敛为模板化、可校验的 SQL 形态，覆盖常用分析场景。

### 7.2 关键内容

- 基础分析：聚合（SUM/COUNT/AVG）、分组、时间趋势（按日/周/月）、TopN（含 tie 处理）。
- 高级分析：同比/环比（含口径：日/周/月对齐）、占比（组内占比）、去重计数、窗口函数（累计、移动平均、排名）。
- 分析参数进入 PlannerOutput / 方案：`analysis_type` 已有，扩展 `analysis_params`（粒度、对比期、窗口）并做合法性校验。
- SQL 模板：`sql_prompts.py` 增加分析型模板，Guardrails 对窗口/子查询做白名单校验。

### 7.3 验收标准

- "上月新增订单环比""各经销商新增订单占比""近 7 天每日新增趋势"等场景稳定出正确 SQL 与结果。
- 分析参数非法（如窗口函数用在明细上）时安全拒绝或澄清，不生成越权 SQL。

## 八、第20课：上下文裁剪与多轮摘要

### 8.1 本课目标

控制长对话下传给 LLM 的 token 规模（配合已上线的 token 统计衡量收益），不丢失关键口径。

### 8.2 关键内容

- 分级保留：最近 N 轮完整保留；更早轮次压缩为摘要（指标、过滤、结果概要）。
- `_build_history_context` 升级：按轮次 + 字符预算裁剪，工具结果只保留摘要。
- 语义层候选 / Schema 上下文 / 查询结果避免长期重复写入消息历史（已有 query_stored_result 替代重查）。
- 摘要写回 State（`topic_summary` 预留字段），不注入前端展示。

### 8.3 验收标准

- 30 轮以上对话，Planner 输入 token 相对不裁剪时显著下降（用 token 统计前后对比）。
- 追问"第三轮的结果"仍能通过索引 + 摘要定位。

## 九、第21课：持久化 Checkpointer 与历史恢复

### 9.1 本课目标

把 `MemorySaver` 替换为持久化 Checkpointer（如 SQLite/MySQL），服务重启后恢复对话、confirmed_plan 与结果索引。

### 9.2 关键内容

- 持久化实现：`langgraph` checkpointer 适配（SQLite 起步，MySQL 可选）；`thread_id=conversation_id` 语义不变。
- 恢复策略：重启后历史消息、确认方案、结果索引（`list_result_index`）可读；执行中的请求标记为失败/丢弃。
- 会话管理：Web 端会话列表从内存 `sessions` 迁移到持久化存储，删除/重命名同步。

### 9.3 验收标准

- 服务重启后，同一 conversation 可继续追问"刚才的结果"，并能读回落盘 CSV。
- 重启不产生重复执行或状态分裂。

## 十、第22课：并发、幂等与失败恢复

### 10.1 本课目标

处理重复请求、并发写入与安全重试，保证系统在多人使用下不串数据。

### 10.2 关键内容

- `request_id` 幂等：同一会话重复提交去重，避免消息重复追加与 SQL 重复执行。
- 同一 conversation 并发修改限制（锁或串行化），防止 confirmed_plan 竞争覆盖。
- 失败恢复分级：安全重试（网络/超时）vs 重新规划 vs 明确报错；与 0 行自愈、并行子查询失败互不干扰。
- 索引构建与查询执行并发安全（避免覆盖稳定索引版本）。

### 10.3 验收标准

- 双击/重复请求只执行一次查询；两个请求同时操作同一会话不丢状态。
- 失败重试不放大执行次数（有上限与退避）。

## 十一、第23课：部署、监控与性能优化

### 11.1 本课目标

健康检查、配置化部署、关键指标统计与性能瓶颈优化。

### 11.2 关键内容

- 健康检查接口、进程守护与配置环境变量化（`.env` 模板）。
- 指标统计：LLM token 消耗（已上线）、各节点耗时、SQL 执行耗时、检索命中率、首查成功率（写日志事件）。
- 性能优化：SQL 执行成本控制（超时/行数上限）、Prompt 长度、元数据缓存命中率。
- 按需接入 Prometheus / Grafana 或直接使用结构化日志仪表化。

### 11.3 验收标准

- 部署后可通过健康检查确认服务状态；关键耗时与命中率可从日志/监控查询。
- 慢查询有明确超时与降级文案。

## 十二、第24课：功能验收与演示闭环

### 12.1 必须通过的场景

1. 语义层命中（精确业务词 → 指标）；2. 语义层未命中走 RAG 兜底；3. 口径歧义澄清；4. 连续追问复用落盘结果；5. 单表/多表 Join；6. 分析性查询（趋势/环比/占比）；7. 0 行自愈（probe_values 修正）；8. 拒绝场景（join 契约缺失 / 无数据告知用户）；9. 多数据源（Hive + Doris）；10. 并行多指标查询；11. 前端真流式 + 思考计时 + token 展示；12. skill 渐进式披露命中（read_skill 调用）。

### 12.2 完成标准

- 业务用户不需要理解物理表/字段/Join。
- 语义层优先、RAG 兜底、安全校验链路完整；失败有明确可解释的澄清或拒绝原因。
- 日志可还原：skill 披露 → read_skill / search_semantic → 工具调用 → SQL 校验 → 执行 → 落盘 → 回答。
