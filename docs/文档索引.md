## 文档维护规则

1. 新增 Markdown 文档时必须放入 `docs/` 下的对应分类目录。
2. 架构发生变化时，优先更新架构专文，再同步项目总览和课程交接文档。
3. State 字段、消息记忆和 Checkpointer 设计以《State 与记忆系统架构》为准。
4. 元数据、FAISS 索引和检索链路以《元数据与向量检索架构》为准。
5. 每节课程结束后，在 `docs/课程复盘/` 新建一份独立 Markdown，不能只更新总课程规划。
6. 课程复盘必须包含实际困难、根因、考虑过的方案、最终取舍、验证场景、当前边界和面试表达。
7. 所有相对链接均以当前文档所在目录为起点，移动文件后必须同步检查链接。
