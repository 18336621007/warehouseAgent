## 文档维护规则

1. 新增 Markdown 文档时必须放入 `docs/` 下的对应分类目录。
2. 架构发生变化时，优先更新架构专文，再同步仓库根目录 README。
3. State 字段、消息记忆和 Checkpointer 设计以《State 与记忆系统架构》为准。
4. 元数据、FAISS 索引和检索链路以《元数据与向量检索架构》为准。
5. 所有相对链接均以当前文档所在目录为起点，移动文件后必须同步检查链接。

## 当前建议阅读顺序

1. 仓库根目录的 `README.md`：快速理解项目定位和启动方式。
2. `架构/Text2SQL系统架构文档.md`：理解整体架构、工具集与执行链。
3. `架构/State与记忆系统架构.md`：理解 QueryPlan、Topic 和 Checkpoint。
4. `架构/元数据与向量检索架构.md`：理解元数据、FAISS、Coverage 和 Join 关系。
5. `架构/语义层架构.md`：理解语义层（权威口径）与双路召回的分工。
6. `指南/日志使用与问题排查指南.md`：从日志还原真实请求的执行过程。
