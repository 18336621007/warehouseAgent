## 文档维护规则

1. 新增 Markdown 文档时必须放入 `docs/` 下的对应分类目录。
2. 架构发生变化时，优先更新架构专文，再同步项目总览和课程交接文档。
3. State 字段、消息记忆和 Checkpointer 设计以《State 与记忆系统架构》为准。
4. 元数据、FAISS 索引和检索链路以《元数据与向量检索架构》为准。
5. 每节课程结束后，在 `docs/课程复盘/` 新建一份独立 Markdown，不能只更新总课程规划。
6. 课程复盘必须包含实际困难、根因、考虑过的方案、最终取舍、验证场景、当前边界和面试表达。
7. 所有相对链接均以当前文档所在目录为起点，移动文件后必须同步检查链接。

## 2026-08-10 文档更新说明

1. `enriched_columns` 新增 `meta_source` 来源标记（`ddl_comment`/`llm_enhanced`），元数据展示按来源分层。
2. 澄清选项、口径区别说明、方案确认统一优先展示字段原始备注；无原始备注才回退 LLM 增强别名并标注“系统推断别名”。
3. 同步更新《元数据与向量检索架构》《多智能体Text2SQL系统架构文档》《多表查询执行过程详解》《课程交接文档》《后续课程规划》。
4. 优秀案例存储改造：`original_question` 保留话题原文、`effective_query` 独立滚动；示例按问题去重（精确 hash + 语义 ≥0.9 且表/字段一致，高分优先）；FAISS 原文召回、`effective_query` 注入；MySQL 与 FAISS hash 口径统一。
5. 最终回答基准修复：`build_final_answer` 回答基准由 `original_question` 改为 `effective_query`（回退原文），已确认口径覆盖只保留 `confirmed_plan.measures` 中指标，修复多轮追问后“数据不足以回答”误判。

## 2026-08-07 文档更新说明

1. 第13课第一阶段落地：去掉 `_CHINESE_NUMBERS`/`_match_by_index` 硬规则，Planner 模型判断 `user_selection` + 程序 `validate_user_selection` 白名单校验。
2. `pending_metric_clarification` 升级为 `pending_clarifications` 注册表，支持单 pending 延迟澄清恢复。
3. `build_final_answer` 写入 `last_query_result` 结果快照，为结果追问提供结构化上下文。
4. 用户询问口径区别时，Advisor 基于候选原始备注/别名/来源表生成口径区别说明，pending 保持 open。
5. 同步更新《多表查询执行过程详解》《后续课程规划》《课程交接文档》。
