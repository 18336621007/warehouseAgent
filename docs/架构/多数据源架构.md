# 多数据源架构（Hive / Doris / Trino）

> 更新日期：2026-09-16
> 项目路径：`D:\code\Project\test`
> 说明：本文档描述三引擎查询架构：**元数据走 Hive、查询走 Trino/Doris**，以及引擎路由、降级与校验机制。

---

## 一、设计原则

1. **引擎是执行层基础设施，不是业务语义**：语义层（metrics / entities / semantic_models / physical）只描述 `schema.table` 与口径，不绑定引擎；`physical.yaml` 中的 `database` 字段仅作参考注释，**不作为路由依据**。
2. **逻辑表唯一，引擎候选可多条**：同一张逻辑表可有多个可用查询通道（有序候选列表），首选失败自动降级。
3. **元数据与查询分离**：表清单/字段结构/枚举采样/RAG 索引继续以 Hive 为权威；查询执行按引擎路由。

## 三、引擎路由配置（单一事实源）

`agentTest/config/datasource_scope.yaml`：

```yaml
engine_scope:
  default: [trino, hive]        # 未匹配库：Trino 优先，Hive 兜底
  databases:
    data_project: [doris]       # data_project 为 Doris 专属，失败直接报错
  # tables:                     # 表级覆盖（预留）
  #   "dws_trip.some_table": [trino, hive]
```

解析优先级：`tables` 精确匹配 > `databases` 库匹配 > `default`。候选列表有序，第一位首选。

程序入口：`agentTest/datasource/registry.py`
- `resolve_engine_candidates(table_identifier)`：按表解析引擎候选链（纯配置，无状态）
- `DataSourceRegistry`：注册引擎执行器（`register`/`get_datasource`/`get_candidates`）

## 四、路由链路

```
用户："美团天数池租赁中订单数"
  └─ Planner 语义层命中 → 指标 source_model = data_project.ads_gundam_boss_meituan_renting_day
       └─ build_plan_from_semantic：resolve_engine_candidates(主表) → plan["engine_candidates"] = ["doris"]
            └─ execute_sql_node：按候选链逐个引擎执行
                 - Doris 首选命中 → 返回结果
                 - Trino 失败 → 降级 Hive 兜底 → 返回结果
                 - 全部失败 → 汇总各引擎错误返回
```

关键实现：

1. **方案携带引擎**：`plan_synthesizer.py` 的 `build_plan_from_semantic` 在 plan 中写入：
   - `engine_candidates`：主表解析出的有序引擎候选链
   - `cross_engine`：多表且其余表首选引擎与主表不一致时为 True（执行层直接拒绝，提示拆开查询）

2. **执行路由 + 降级**：`execute_sql_node.py` 按 `engine_candidates` 逐个调用 `sql_query_<engine>` 工具：
   - 连接/执行异常（RuntimeError 等）→ 降级下一个候选
   - 校验失败（ValueError，如 select * 门禁/白名单）→ 不降级，直接返回（换引擎大概率同样拒绝）
   - 全部候选失败 → 返回 `"[engine1] err；[engine2] err"` 汇总错误

3. **工具注册**：`tool_factory.py` 为每个引擎注册独立工具 `sql_query_trino / sql_query_hive / sql_query_doris`（内部都是 `SQLQueryTool` + 对应 `DataSource`）。

### Trino 偶发 404 与自动重试

**现象**：Trino 首查偶发 404（日志 `trino.retry` 事件），表现为 `POST /v1/statement` 建查询成功（200），但随后 `GET /v1/statement/queued/{query_id}/{token}` 返回 `404 Query not found`。

**根因**：Trino 多 coordinator 负载均衡**非粘滞路由**——POST 打到节点 A，GET 状态被路由到节点 B，节点 B 上找不到该 query_id。这是服务端配置问题，客户端无法根治；host 全程正确，与系统代理无关。

**客户端策略**（`trino_datasource.py`）：

1. **自动重试**：`query()` 对 404 自动重试（最多 2 次、共 3 次尝试），每次新建连接重新发起查询；404 发生在查询执行前（客户端尚未消费结果），重试不会叠加查询执行时间，仅多花连接 + POST 的开销。
2. **短暂退避**：每次 404 重试前 `time.sleep(0.5)`（`RETRY_BACKOFF_SECONDS`），给负载均衡恢复粘滞的时间。
3. **重试日志**：重试事件直接写入 `logs/langgraph_app.jsonl`，`event=trino.retry`（重试前）/ `event=trino.retry_success`（重试后成功），含 `attempt/retry_count/elapsed_ms/error/sql`，用于线上统计 404 触发频率与恢复情况；该日志不带 `request_id`，关联具体请求请用 `execute_sql` 节点的 `node.completed(engine=...)`。
4. **耗尽降级**：3 次尝试仍 404 时抛 `RuntimeError`，由 `execute_sql_node` 按候选链降级 Hive 兜底（属期望行为）。

## 六、元数据分工

- **Hive**（`HiveMetadataProvider`）：表清单、字段结构、白名单过滤、缓存——维持现状
- **语义层 physical 兜底**（`SemanticMetadataProvider.describe_table`）：Hive 查不到的表（如 `data_project` 3 张天数池表）从语义层 YAML 构造字段结构
- **多源包装**（`agentTest/metadata/multi_source_meta_provider.py` `MultiSourceMetadataProvider`）：`describe_table` 先 Hive、失败自动降级语义层 physical
- **字段-表归属校验**：`query_plan_service._build_table_columns_index` 在 MySQL 增强元数据基础上叠加语义层 physical 字段，保证 `data_project` 等 Doris 专属表通过 `validate_field_table_bindings`

> 注：`data_project` 表不在 Hive 中，`list_tables` 会跳过该库（Hive 侧库不存在），但白名单 `metadata.yaml` 已包含这 3 张表，语义层命中后直接按表精确 describe/执行，不依赖库级扫描。

## 七、安全校验（三引擎统一底线）

`SQLQueryTool.run` 对所有引擎统一执行同一套校验（不再区分 Hive/Trino/Doris）：

1. `is_read_only_sql`：只读（SELECT/WITH 开头、禁止多语句）
2. `validate_hive_sql`：LIMIT 必须、JOIN 开关、白名单库表
3. `validate_sql_with_guardrails`：AST 级 select * 门禁、逐表时间分区过滤

引擎差异仅在执行层（连接协议/语法方言），安全底线一致。`probe_values` 值探查工具也按表解析引擎（`engine_registry`）执行。

## 九、运维指引

- **新增引擎**：实现 `BaseDataSource` 子类（`engine` 属性）→ 在 `datasource_scope.yaml` 配置候选 → 在 `tool_factory.ENGINE_DATASOURCES` 注册 → 在 `graph_runtime` 的 `datasource_registry` 注册
- **改某表路由**：只改 `datasource_scope.yaml`（表级覆盖），无需改代码
- **元数据兜底**：Hive 无元数据的表，确保语义层 `physical/<schema>/<table>.yaml` 有字段定义
- **降级策略**：`data_project` 失败直接报错（唯一通道）；其他表 Trino 失败自动切 Hive；校验失败不降级
