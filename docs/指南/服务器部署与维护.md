## 一、服务器基本信息

- 主机名：`TM6088`
- 内网地址：`http://10.14.50.4:5000`
- 项目代码目录：`/opt/gy-data-agent/bd-skills`
- 仓库分支：`gy-data-agent`
- 虚拟环境：`/opt/gy-data-agent/.venv`
- 启动入口：`python web/server.py`（根目录在 `bd-skills`）
- 服务方式：systemd 托管，服务名 `dataagent`
- 依赖：MySQL（仅语义层模式，数据库 `data_agent`）；RAG/embedding 已关闭（`ENABLE_RAG=false`）

## 二、目录与资产说明

```text
/opt/gy-data-agent/
├── .venv/                          # Python 虚拟环境（build 时创建）
└── bd-skills/                      # git 仓库（gy-data-agent 分支）
    ├── agentTest/
    │   ├── .env                    # 环境变量（gitignore，部署后手工维护）
    │   ├── semantic_layer/         # 语义层 YAML + provider（部分被 gitignore，必须单独同步）
    │   └── skills/gy-offline-nlq/  # skill（SKILL.md / references/faq.yaml 随 git 同步）
    ├── web/
    │   ├── server.py               # Flask 后端入口
    │   └── static/                 # 前端
    └── ...
```

重点：

- `agentTest/semantic_layer/` 下大量 YAML（metrics / semantic_models / physical / join_contracts 等）**不在 git 中**，每次语义层更新都要单独传到服务器同一路径，不能被代码 `git pull` 覆盖或漏掉。
- `agentTest/.env` 不在 git 中，服务器上的环境配置需要手工维护。
- `agentTest/langgraph_app/cache/checkpoints.db`（LangGraph Checkpoint）和 `agentTest/query_results/`（查询结果落盘）为运行时生成，可写即可。

## 三、环境安装（首次部署）

```bash
cd /opt/gy-data-agent/bd-skills
python3 -m venv /opt/gy-data-agent/.venv
/opt/gy-data-agent/.venv/bin/pip install --upgrade pip
/opt/gy-data-agent/.venv/bin/pip install -r agentTest/requirements.txt
```

> 若服务器无法编译 `faiss-cpu` 且使用 `ENABLE_RAG=false`，可先跳过 faiss：安装时删除 requirements 中的 `faiss-cpu` 行，后续需要 RAG 再补装。

## 六、systemd 维护

服务文件：`/etc/systemd/system/dataagent.service`

```ini
[Unit]
Description=DataAgent Query Service
After=network.target mysql.service

[Service]
Type=simple
WorkingDirectory=/opt/gy-data-agent/bd-skills
EnvironmentFile=/opt/gy-data-agent/bd-skills/agentTest/.env
ExecStart=/opt/gy-data-agent/.venv/bin/python /opt/gy-data-agent/bd-skills/web/server.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

常用命令：

```bash
systemctl daemon-reload
systemctl enable --now dataagent     # 启动并开机自启
systemctl start dataagent            # 启动
systemctl stop dataagent             # 停止
systemctl restart dataagent          # 重启
systemctl status dataagent           # 状态
journalctl -u dataagent -f           # 实时日志
journalctl -u dataagent -n 50 --no-pager   # 最近 50 行
```

启动正常标志：

```text
[server] runtime ready
[feishu] 飞书机器人已启动（长连接）
Running on http://10.14.50.4:5000
```

## 七、日常维护流程

### 7.1 更新代码

```bash
cd /opt/gy-data-agent/bd-skills
git pull
systemctl restart dataagent
systemctl status dataagent
```

### 7.2 更新语义层资产（关键）

语义层 YAML 不在 git 中，需要从本机打包同步到服务器，覆盖 `agentTest/semantic_layer/` 后重启：

```bash
rsync -av --exclude="__pycache__" ./semantic_layer/ root@TM6088:/opt/gy-data-agent/bd-skills/agentTest/semantic_layer/
systemctl restart dataagent
```

### 7.3 更新 .env

修改 `/opt/gy-data-agent/bd-skills/agentTest/.env` 后：

```bash
systemctl restart dataagent
```

### 7.4 查看访问是否正常

```bash
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:5000/
```

返回 `200` 即正常。内网同事访问：

```text
http://10.14.50.4:5000
```

## 九、常见问题

### 9.1 systemd 启动 203/EXEC

原因：`ExecStart` 里的 python 路径不存在。

排查：

```bash
ls -l /opt/gy-data-agent/.venv/bin/python
```

修正 `/etc/systemd/system/dataagent.service` 中的 `ExecStart` 后：

```bash
systemctl daemon-reload
systemctl restart dataagent
```

### 9.2 MySQL 连接不上 / 服务启动失败

确认 MySQL 已启动、库已创建、`.env` 的库名和账号密码与 MySQL 一致：

```bash
systemctl status mysql
mysql -u root -p123456 -e "SHOW DATABASES;"
```

### 9.3 语义层没有生效

检查 `agentTest/semantic_layer/` 下是否有 YAML 文件且已同步到服务器同一路径：

```bash
ls /opt/gy-data-agent/bd-skills/agentTest/semantic_layer/metrics | head
```

## 十、安全与规范

- 当前 root 密码 `123456` 仅用于内网测试，正式环境务必更换强口令并把密码从本文档中移除。
- `.env` 含敏感信息，不要提交到 git，也不要普通编辑权限共享给无关人员。
- systemd 已开启 `Restart=always`，异常退出会自动拉起；排查时先看 `journalctl` 再重启。
- 代码仓库应始终在 `bd-skills` 子目录内操作，不要在 `/opt/gy-data-agent` 根目录执行 git 命令（那里不是 git 仓库）。
